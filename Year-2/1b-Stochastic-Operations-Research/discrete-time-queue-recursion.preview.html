Discrete-Time Queue Recursion¶

Method¶

Divide time into periods k=1,2,…k=1,2,\dotsk=1,2,… of equal length and let

  • aka_kak​ be the number of jobs that arrive in period kkk,
  • ckc_kck​ the capacity, the maximal number of jobs that can be served in period kkk,
  • dkd_kdk​ the number of jobs that depart just before the end of period kkk,
  • LkL_kLk​ the number of jobs in the system at the end of period kkk; so Lk−1L_{k-1}Lk−1​ is also the number at the start of period kkk.

Given L0L_0L0​ and the sequences {ak}\{a_k\}{ak​} and {ck}\{c_k\}{ck​}, the queue is constructed period by period. If jobs that arrive in period kkk cannot be served in that period,

dk=min⁡{Lk−1,ck},Lk=Lk−1−dk+ak.d_k=\min\{L_{k-1},c_k\},\qquad L_k=L_{k-1}-d_k+a_k.dk​=min{Lk−1​,ck​},Lk​=Lk−1​−dk​+ak​.

If they can be served in the period of arrival,

dk=min⁡{Lk−1+ak,ck},Lk=Lk−1+ak−dk=[Lk−1+ak−ck]+,d_k=\min\{L_{k-1}+a_k,c_k\},\qquad L_k=L_{k-1}+a_k-d_k=[L_{k-1}+a_k-c_k]^+,dk​=min{Lk−1​+ak​,ck​},Lk​=Lk−1​+ak​−dk​=[Lk−1​+ak​−ck​]+,

where x+=max⁡{x,0}x^+=\max\{x,0\}x+=max{x,0} is the positive part. In both versions service is work-conserving: capacity is never left unused while there are jobs it may serve. Jobs are not counted as being "in service", so LkL_kLk​ is both the number in the system and the number in queue.

Interpretation¶

The recursion is bookkeeping: the jobs present at the start of a period, minus those that leave, plus those that arrive. The minimum keeps the server from serving jobs that are not there. Only counts per period are needed, not individual inter-arrival or service times.

The figure plots Example 1: L0=2L_0=2L0​=2, arrivals 3,0,4,1,03,0,4,1,03,0,4,1,0 and capacity ck=2c_k=2ck​=2. Both versions agree for two periods. In period 3 only one job is waiting when four new jobs arrive; if new jobs must wait for the next period, one unit of capacity is lost and L3=4L_3=4L3​=4, while serving on arrival gives L3=3L_3=3L3​=3. From then on the first version stays above the second, ending at L5=1L_5=1L5​=1 against 000.

The timing is a modelling choice, not a law. The notes advise the first recursion when one wants to be on the safe side: it overestimates queue lengths, the second underestimates them. Work conservation is also an assumption; an airline that cancels a nearly empty flight does not serve waiting customers although it could. The recursion produces {Lk}\{L_k\}{Lk​} and {dk}\{d_k\}{dk​} only. Waiting times of individual jobs need, in addition, the order of service, and the course uses first-in-first-out (FIFO) throughout.

3. Algorithm 2.2.1 in Python. The version with service in the arrival period:

def queue_lengths(a, c, L0=0):
    L = [L0]
    for ak, ck in zip(a, c):
        d = min(L[-1] + ak, ck)   # departures in this period
        L.append(L[-1] + ak - d)
    return L

print(queue_lengths([3, 0, 4, 1, 0], [2] * 5, L0=2))   # [2, 3, 1, 3, 2, 0]
