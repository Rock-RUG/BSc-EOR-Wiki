(s, S) Policy¶

Definition¶

In a periodic-review single-item inventory system, an (s,S)(s,S)(s,S) policy with reorder level sss and order-up-to level SSS, integers with s<Ss<Ss<S, places at the start of period kkk the order

Qk=(S−Pk−1′) 1{Pk−1′≤s},Q_k=(S-P_{k-1}')\,\mathbf{1}\{P_{k-1}'\le s\},Qk​=(S−Pk−1′​)1{Pk−1′​≤s},

where Pk−1′P_{k-1}'Pk−1′​ is the end-of-period inventory position of period k−1k-1k−1 and 1{⋅}\mathbf{1}\{\cdot\}1{⋅} is the indicator. Thus, when the position has fallen to sss or below, it is raised to SSS; otherwise nothing is ordered.

Interpretation¶

An (s,S)(s,S)(s,S) policy lets demand accumulate before it orders. Each order carries a fixed setup cost KKK, so reordering every unit at once, as the base-stock policy does, is expensive; the gap S−sS-sS−s bundles several periods of demand into one order.

The orders, 666, 777 and 777, differ because demand pushes the position below sss by different amounts.

The test is "at or below sss", not "equal to sss": demand of several units usually jumps past sss, and the order S−P′≥S−sS-P'\ge S-sS−P′≥S−s makes up the undershoot. The test uses the position, so units on order are not ordered again. With s=S−1s=S-1s=S−1 every period with positive demand triggers an order: the base-stock policy.

Compared with EOQ with lead times, where a fixed batch is ordered at a reorder level, the batch now varies with the undershoot and the order epochs are random. A supermarket can use the policy for yogurt, with SSS fixed by the shelf space. There is generally no closed formula for the best (s,S)(s,S)(s,S), so the notes simulate each pair on one demand list and search a grid. Week 6 computes the exact long-run cost with a hitting-time recursion.

2. The simulation of the notes. The following Python function follows Algorithm 2.5.1: it starts with P1=I1=SP_1=I_1=SP1​=I1​=S and nothing on order, charges KKK per order, hhh per unit on hand and bbb per unit backlogged at the start of each period, and returns the average cost.

def simulate_ss(d, s, S, l, K, h, b):
    n = len(d)
    P, I = S, S                     # start of period 1, nothing on order
    Q = [0] * (n + 2)               # Q[k]: order placed at the start of period k
    cost = 0
    for k in range(1, n + 1):
        cost += K * (Q[k] > 0) + h * max(I, 0) + b * max(-I, 0)
        P, I = P - d[k - 1], I - d[k - 1]   # end of period k
        Q[k + 1] = S - P if P <= s else 0
        P += Q[k + 1]
        I += Q[k + 1 - l] if k + 1 - l >= 1 else 0
    return cost / n
