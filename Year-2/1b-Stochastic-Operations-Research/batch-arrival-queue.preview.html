Batch-Arrival Queue¶

Definition¶

In the MB/M/1M^B/M/1MB/M/1 queue jobs arrive in batches. Batches arrive as a Poisson process with rate λB\lambda_BλB​, and the numbers of jobs in the batches are i.i.d. copies of a batch size B∈{1,2,… }B\in\{1,2,\dots\}B∈{1,2,…}. The service time Sk,iS_{k,i}Sk,i​ of the iiith job of batch kkk is an i.i.d. copy of S∼Exp⁡(μ)S\sim\operatorname{Exp}(\mu)S∼Exp(μ), independent of the batch sizes. There is one server. An arriving batch joins the end of the queue; when it reaches the head of the queue, the whole batch moves to the server, which then serves its jobs one after another.

Jobs arrive at rate λ=λBE[B]\lambda=\lambda_B\mathbb{E}[B]λ=λB​E[B], so the load is

ρ=λB E[B] E[S],\rho=\lambda_B\,\mathbb{E}[B]\,\mathbb{E}[S],ρ=λB​E[B]E[S],

and, as always, ρ<1\rho<1ρ<1 is required. Write LLL for the number of jobs in the system, QBQ^BQB for the number of batches in queue, LsBL_s^BLsB​ for the number of jobs of the batch at the server (zero if the server is idle), and G(i)=P(B>i)G(i)=\mathbb{P}(B>i)G(i)=P(B>i) for the survivor function of BBB.

Interpretation¶

A single arrival event can bring several jobs at once, so the number in the system jumps up by a whole batch but still goes down one job at a time. Even with the same job arrival rate and service rate as an M/M/1 queue, queues are longer (unless every batch contains a single job), because the jobs of one batch must wait for each other.

The Poisson assumption concerns the batches: by PASTA, arriving batches see time averages, so π(n)=p(n)\pi(n)=p(n)π(n)=p(n). Individual jobs do not arrive as a Poisson process, because jobs of the same batch arrive at the same moment (TF 5.3.3). By the memoryless property of exponential services, the number of jobs alone describes the state, so a level-crossing argument applies. The new feature is that one batch can up-cross several levels at once: a batch that sees m≤nm\le nm≤n jobs up-crosses level nnn exactly when it contains more than n−mn-mn−m jobs.

In Kendall's notation the superscript BBB marks the batches. The same batching model returns in Week 6 for batch processing with server setups.

  • Mean waiting time. The batch-arrival waiting time formula (5.3.4) gives E[W]\mathbb{E}[W]E[W] and, by E[W]=E[L] E[S]\mathbb{E}[W]=\mathbb{E}[L]\,\mathbb{E}[S]E[W]=E[L]E[S], also E[L]\mathbb{E}[L]E[L]; it requires E[B2]<∞\mathbb{E}[B^2]<\inftyE[B2]<∞.
  • Level crossing with batches (5.3.5). For n≥0n\ge0n≥0, λB∑m=0nπ(m)G(n−m)=μ π(n+1)\displaystyle \lambda_B\sum_{m=0}^{n}\pi(m)G(n-m)=\mu\,\pi(n+1)λB​m=0∑n​π(m)G(n−m)=μπ(n+1).   • No closed form. In general the recursion does not give π(n)\pi(n)π(n) in closed form. Numerically, start with q(0)=1q(0)=1q(0)=1, apply the recursion until the weights are negligible (for a batch size bounded by KBK_BKB​, compute at least KBK_BKB​ values first), and normalize.   • Rejecting batches instead bounds the state space; see batch rejection policies.

The code below, a Python version of the notes' algorithm, reproduces these values; its mean is E[L]=4/3\mathbb{E}[L]=4/3E[L]=4/3, against ρ/(1−ρ)=1\rho/(1-\rho)=1ρ/(1−ρ)=1 for an M/M/1 queue with the same load.

def batch_stationary(lam_B, mu, G, K_B, eps=1e-10):
    q = {0: 1.0}
    n = 0
    while n < K_B or q[n] > eps:
        q[n + 1] = lam_B / mu * sum(q[m] * G(n - m) for m in range(n + 1))
        n += 1
    total = sum(q.values())
    return {n: qn / total for n, qn in q.items()}

G = lambda i: {0: 1.0, 1: 0.5}.get(i, 0.0)   # B = 1 or 2, each w.p. 1/2
pi = batch_stationary(1, 3, G, K_B=2)
print(round(pi[0], 4), round(pi[1], 4))      # 0.5 0.1667
